一、8.11 之后的更新总览

01
  1. 1型号资料更新到最新版本。 做表和 SKU 修复现在使用印尼 8.19 型号表与菲律宾 9.6 型号表，旧的 7.12 / 8.12 资料不再作为当前规则入口。
  2. 2做表价格与型号匹配更严格。 只读取标准的书本、笔槽、3Y、旋转价格档；纯色和 BB-笔不会污染标准价格，价格冲突会阻止导出，无法识别的型号不会静默猜测。
  3. 3适配 BigSeller 更新后的标题输入框。 标题读取、填写和复核改按稳定的 autoid="product_name_text" 定位，不再要求输入框必须带旧版 ant-input class。
  4. 4Shopee 和 TK 的进度状态可以断线校准。 两个平台仍然使用独立 Worker、独立 SSE 和独立状态；SSE 断开、页面重新获得焦点或网络恢复后，界面会用紧凑状态接口补齐最新进度。
  5. 5旧链接折扣增加安全判断。 只比较折扣列里非空且有效的数值；全部数值一致才会批量更新，不一致、无效或没有数值时自动跳过并记录原因。
  6. 6图片参数可以在当前范围内联动。 联动严格限制在当前平台、当前生效店铺、当前模板和当前通用类型；只同步指定的四项图片参数，主图、变种图、偏移、标题和视频仍然独立。
  7. 7页面结构变化和发布收尾继续安全化。 变种表会等待稳定结构并动态识别列；发布成功以本次成功提示为准，BigSeller 自动关闭编辑页不会再被误判为失败。

三、标题输入与店铺方案

03

本次 BigSeller 页面把标题输入框的 class 从旧的 ant-input 变成了带有新版样式的输入框，导致旧定位器等待 10 秒后出现 FATAL。现在程序按稳定属性定位，因此只要当前确实位于正确的编辑页，标题可以继续填写和复核。

标题定位不再绑旧 class

标题填写、编辑页标题读取、品牌二次确认和保存后复核都使用 input[autoid="product_name_text"]。页面样式 class 变化不会再单独造成标题定位超时。

标题规则继续按配置

标题里的品牌前缀、品牌、型号和功能词仍由当前模板配置决定；需要 For 时手动写入，型号之间的 / 不要改成空格。

店铺方案按平台隔离

Shopee 与 TikTok Shop 分别保存、应用、重命名和删除店铺方案。新建方案只清空标题内容，图片、视频、品牌开关等基础配置继续保留；AI 密钥和本机路径不写入店铺方案。

如果更新文件后仍看到旧的标题定位错误，先完整重启上架工具，让 Worker 和服务端加载新代码，再用 1 个 Item ID 测试。

四、批量开启旧链接折扣

04

“批量开启旧链接折扣”是独立工具，针对 BigSeller 列表页已有的旧链接促销。它不会进入商品编辑页，也不会把促销价、限购输入框或其他数字误当成折扣。

打开正确列表页在 BigSeller 打开 Shopee 产品列表页，输入 Item ID。工具会从列表页的促销价入口打开对应促销弹窗。
先开启全部变种进入促销弹窗后先确认全部变种开关，再识别标题为“折扣”的列和其中的 % OFF 输入值。
只比较非空折扣空白折扣不参与比较；非空值必须是 0–100 的有效数值。所有有效值相同，才允许继续批量编辑。
统一后等待成功批量填写原有一致的折扣，确认“应用到所有变种”，点击更新并等待成功提示，然后关闭弹窗进入下一个 Item。

不一致自动跳过

折扣值不一致、存在无效非空值或完全没有可比较数值时，不会强行覆盖，任务会关闭弹窗并在结果中记录具体跳过原因。

与普通批量折扣分开

旧链接工具按页面现有折扣自动判断；普通“批量开启折扣”仍按用户填写的目标百分比处理。使用前确认入口名称，避免操作错工具。

五、进度、变种表与发布稳定性

05
  1. 1SSE 增加心跳和断线恢复。 Shopee 使用 /events，TK 使用 /events-tk；页面会在 SSE 重连、窗口重新获得焦点或网络恢复时请求当前紧凑状态。
  2. 2进度按真实商品完成更新。 当前批次的商品完成数和已完成批次基数分开计算；批次报错不会被错误标记为完成，两个平台的进度不会互相覆盖。
  3. 3变种表结构必须稳定。 工具会动态识别 Color、Model、SKU、库存、价格、重量等列，并对临时重复或缺失的行等待复核；持续冲突时安全暂停。
  4. 4继承值和成功收尾更可控。 添加新 Model 时先清理 BigSeller 继承的 SKU、库存和价格；发布后只有看到本次成功提示才算成功，编辑页自动关闭会正常收尾。
界面上的进度是服务端状态的展示。遇到 SSE 短暂断开时先看当前商品和日志，不要立即刷新或手动关闭编辑页。

六、图片参数联动与冲突检查

06

设置里新增“图片参数联动”后，可以在当前配置范围内统一重复参数，减少多品牌逐项填写的工作量。联动不是全局覆盖，范围会跟随当前平台、当前生效店铺、当前模板；通用模板还会继续区分当前的 3Y、书本、笔槽或旋转类型。

只同步四项

联动的字段是每组图数、辅图数量、AI 识别图和跳过序号。主图序号、变种图序号、品牌偏移、标题、视频和品牌顺序继续各自独立。

保存前检查图片上限

系统会检查跳过序号是否和主图、变种图或 AI 图冲突，并检查产品图总数是否超过 9 张；冲突或超限时不会静默保存。

随机主图也受保护

启用单品牌主图随机模式时，主图和变种图候选序号会分别校验，跳过序号不能与任何候选重复。

修改图片参数后先抽查一个品牌：确认主图排第一、详情图数量不超过 9 张、变种图与页面 Color 一一对应，再开始整批上架。

二、批量修改错误 SKU 使用方法

02

入口在主界面顶部“偷懒小工具”中的“批量修改错误 SKU”。适合已有商品的 Model 正确、但部分 SKU 前缀或颜色编号写错时统一核对。

准备列表页在 BigSeller 打开 Shopee 在线产品列表页，并选择一个具体店铺。不要停在编辑页，也不要同时打开多个 Shopee 在线列表页。
选择规则依次选择菲律宾或印尼、书本/笔槽/旋转/3Y 类型以及商品品牌。选择项变化后需要重新打开安全确认。
填写 Item ID每行粘贴一个 Item ID。建议第一次先放 1 个商品，确认型号表和页面 Model 完全对应后再跑整批。
开启安全确认确认当前店铺、地区、类型、品牌和型号表无误，再打开安全确认开关并开始。
等待完整核对工具会开启全部 Model，检查行数是否等于已启用 Color × 全部 Model，并为每一行生成正确 SKU。
查看处理结果原 SKU 正确的行不会重复写入；只有不一致的行会修改。每个商品完成后会显示检查行数和修正行数。

SKU 生成规则

完整 SKU 为“型号表中的 SKU 编号 + 连字符 + Color 中的颜色编号”。例如型号前缀为 SXZ-HMSE#11、Color 为 Y132，结果就是 SXZ-HMSE#11-Y132。

不会猜未知型号

页面 Model 必须与型号表的“线上sku名称”准确对应。未知型号、同名冲突、重复变种或无法唯一识别的颜色编号都会暂停整批任务。

三、批量添加新型号升级

03
  1. 1Model 和 SKU 前缀仍由用户填写。 这个工具不读取 PH/ID 型号表；它按输入的新 Model、SKU 前缀和页面 Color 生成新变种。
  2. 2只填写新 Model 的精确行。 工具临时关闭旧 Model 后，只对“Color + 新 Model”唯一匹配的行写入 SKU、库存和价格。
  3. 3旧行必须保持不变。 重新开启全部 Model 后，工具会检查原有 SKU、库存、价格、重量和尺寸，任何意外变化都会暂停。
  4. 4已存在的型号自动跳过。 重跑同一批 Item 时，已经成功添加的新 Model 不会重复创建，可以安全继续后面的商品。
  5. 5颜色编号兼容范围扩大。 支持 Y132 这类单字母编号，也继续支持 KK001 等编号；同一 Color 出现多个候选编号时仍会暂停。
批量添加型号仍受平台 100 个变种上限约束。正式执行前先核对“启用 Color 数量 × 全部 Model 数量”，并优先用 1 个商品测试价格、库存和 SKU 结果。

二、Shopee / TK 主图上传底层调整

过去 9 张产品图会作为同一批文件交给 BigSeller。多数情况下页面会保留文件顺序，但图片大小和网络速度不同，详情小图也可能先完成上传，造成首张缩略图偶尔不是预定主图。本次把产品图上传拆成两个阶段。

第一阶段：只传主图只提交图片列表中的第 1 张主图，不让另外 8 张详情图同时竞争上传完成顺序。
等待主图稳定持续检查主图缩略图已经加载完成、存在有效地址、没有上传或进度状态，并要求连续 3 轮读取一致。
第二阶段：上传详情图主图稳定后，再一次性上传剩余详情图；不足 9 张时按实际图片数量处理。
复核完整图片组等待全部缩略图加载完成且状态稳定，最终图片数量不对时仍会进入原有重试或停止逻辑。

Shopee 与 TK 同时生效

两个平台仍使用各自独立的 Worker 和发布流程，但产品图都采用相同的“主图先传、稳定后再传详情图”策略。

没有取消原有安全检查

旧图必须先删除干净；主图阶段失败、完整图片数量不足或缩略图长期不稳定时，不会直接进入视频、变种图或发布步骤。

最近上架商品卡片仍使用本次上传主图的缩略图，不使用发布前页面截图。正式批量前建议先上架 1 个商品，确认编辑页首图和最近商品缩略图一致。

三、批量添加新 Model 适配 BigSeller 新逻辑

03

BigSeller 官方优化在线产品编辑页后，即使工具已经关闭全部旧 Model，再添加并仅启用新 Model，页面仍会把第一个旧 Model 的 SKU、库存和价格复制到所有新行。SKU ID 虽然显示为 --，输入框里的旧值却真实存在，不能直接当作空白新行。

保存旧行基线先读取全部旧 Model 的 SKU、库存、价格、重量和尺寸，后续任何旧行变化都会停止。
只保留新 Model添加目标 Model 后，确认表格中每一行都是“启用 Color + 新 Model”，不允许混入旧 Model。
先清空继承数据逐行清空 SKU、库存和价格，不触碰促销价、SKU ID 或其他字段；任一输入框不可编辑都会安全暂停。
三轮空值复核连续检查表格行集合和空值状态。如果 BigSeller 又把旧值带回来，任务会在写新数据前停止。
再填写目标数据确认全部为空后，才按 Color + 新 Model 精确填写新 SKU、库存、价格以及页面支持的重量和尺寸。
恢复并核对全部 Model重新开启全部 Model，三轮确认新行正确、旧行完全没有变化后，才允许点击更新。

四、标题规则与上架表格一键制作

04

标题不再自动添加 For

标题固定顺序为“AI 图案词 → 品牌前缀 → 品牌 → 型号 → 功能词”。需要 For 时由用户写在自己的配置字段中，系统不会额外添加或删除字段里的内容。

型号搜索分隔符保持不变

型号使用 / 或全角 ／ 分组；随机只改变组的顺序，输出仍用 / 连接。功能短语使用英文逗号或分号分隔，逗号前后的空格不影响识别。

AI 只识别图片图案

ai_image_shuffle 模式只让 AI 返回 2–3 个图案词；品牌、品牌前缀、型号和功能词均由本地规则生成，不交给 AI 重写。

做表平台限制分开

“上架表格一键制作”新增上架平台选择。选择 Shopee 时单品牌型号数 × Color 数超过 100 不能导出；选择 TK 时不执行这一限制。

标题设置示例：如果希望出现 For Samsung Galaxy Tab，请把 For 写入品牌前缀或其他固定字段。不要等待系统自动补充。

五、通用品牌配置与上架进度

05

删除品牌不再导致后续配置串位

通用全部品牌的动态槽位不再因为删除中间卡片就整体重新编号。剩余品牌保留各自身份，只重新计算实际图片批次偏移。

重新添加同一品牌可恢复配置

删除的品牌会按类型保存原槽位、图片、标题和视频等参数；之后重新选择同一品牌时优先恢复，不会套用其他品牌的方案。

每完成一个商品立即更新进度

当前批次每收到一个商品完成事件，已处理数量就立即增加，不需要等整批结束后才跳动。

批次切换与错误状态更清楚

完成一批后保存该批次基数，下一批在此基础上逐商品累计；收到批次错误时保持未完成状态，不会把错误批次加入已完成列表。

旧店铺不会被覆盖

新建使用新的方案 ID。之前保存的店铺标题、模板和基础配置继续保留；要修改旧店铺，应先应用旧店铺并使用原名称更新。

清空的是标题前缀、品牌、型号、功能词、后缀和固定标题格式；模板结构、品牌启用状态、图片/视频参数和平台开关继续保留。

AI Key、模型、端点和本机图库/Excel路径不写入店铺方案；标题模式和通用提示词作为模板规则保留。

新建后第一次上架前，必须重新检查每个启用品牌的标题字段。若需要沿用旧店铺标题，请应用旧店铺，不要用“新建店铺”代替复制。

爱弥斯在主界面左上角，点击吉祥物即可打开。现在分为两个方向：AI 分析和 AI 聊天。

AI 分析

导入上架表格和图库后，可以让爱弥斯简单分析产品标题、描述、图片和可能的上架风险。它适合做辅助检查，例如标题是否太长、描述是否缺少重点、主图风格是否清楚、型号和品牌是否容易混淆。

AI 分析只是辅助判断，不会替代最终人工确认。正式上架前仍建议核对表格、图片、变种顺序和截图。

AI 聊天

AI 聊天基于大模型，可做部分记忆对话、翻译、标题改写、描述润色、简单解释和操作建议。目前没有设置天气之外的联网查询能力，所以涉及实时网页、最新政策、平台规则变化等内容时，以实际页面和平台通知为准。

三、偷懒小工具新增功能

03

入口在主界面顶部的“偷懒小工具”。这些工具主要用于 BigSeller 已有商品的后处理，和正式 Shopee/TK 批量上架互相独立。

批量添加新型号

重点功能

适合给已经在线的商品批量追加一个新型号，例如新增某个平板型号、颜色组或特殊型号。工具会按 Item ID 搜索商品，进入编辑页，添加新型号，填写 SKU、库存、价格，然后更新商品。

使用前请先在 BigSeller 打开对应平台的产品列表页，并确认当前页面能搜索到这些 Item ID。批量工具不会重新导航页面，它会直接操作你已经打开好的 BigSeller 页面。
准备 Item ID在 BigSeller 产品列表里筛选需要处理的商品，复制每个商品的 Item ID。一个商品一行，最多建议一次放 50 个以内。
打开工具回到控制面板，点击“偷懒小工具”，选择“批量添加新型号”。
填写参数粘贴 ID，填写新 Model 名称、SKU 前缀、库存、价格。SKU 前缀建议清楚稳定，不要和旧 SKU 混淆。
检查 BigSeller 页面确认当前 BigSeller 页面停留在产品列表页，不要停在编辑页或其他弹窗里。
开始执行工具会逐个搜索 Item ID，打开编辑页，进入销售信息，关闭旧型号勾选，新增新型号并填写数据。
等待验证工具会多次检查新 SKU 是否填写正确。如果 SKU 检查失败，工具会立即停止，避免发布错误型号。
查看结果每个 Item ID 会显示成功或失败。失败时先看日志，再检查商品是否能搜索到、是否超过变种数量限制、编辑页是否有异常弹窗。
如果商品颜色很多，新增型号后可能超过平台变种上限。工具会尝试从末尾减少颜色数量来控制总变种数，但仍建议批量执行前先拿 1 个商品测试。

批量开启折扣

配合型号工具

这个功能通常和“批量添加新型号”配合使用。添加新型号后，把需要处理的 Item ID 输入到折扣工具，设置折扣百分比，就可以批量打开促销价并应用到所有变种。

准备 Item ID可以使用刚才批量添加新型号处理过的 Item ID，也可以手动整理一批需要设置折扣的商品 ID。
打开工具点击“偷懒小工具”，选择“批量开启折扣”。
填写折扣粘贴 Item ID 列表，填写折扣百分比。例如填写 49，表示设置为 49% 折扣。
确认列表页保持 BigSeller 产品列表页打开，工具会在列表页直接点击促销价链接，不会进入商品编辑页。
开始执行工具会逐个搜索商品，打开“编辑促销价”弹窗，开启总开关，批量编辑折扣，并应用到所有变种。
核对结果完成后看日志是否出现更新成功。建议抽查 1 到 2 个商品，确认折扣已经应用到所有变种。

一键修改描述

辅助功能

这个功能目前属于辅助性质比较强的鸡肋功能，适合临时批量调整描述内容。具体用法可以自行探索，正式大量处理前建议先拿少量商品测试，确认描述内容和保存效果符合预期。

上架表格一键制作

表格生成

这是本次新增里比较强的功能。工具内置 2026.6.30 最新型号表，上传价格表后，选择品牌和颜色，就可以一键制作 BigSeller 上架表格。

准备价格表先准备好价格表，确保价格、型号、品牌或可识别字段没有明显空行和错位。
打开工具点击“偷懒小工具”，选择“上架表格一键制作”。它会以独立页面形式显示在主界面浮窗里，不影响当前上架面板。
上传价格表在工具中上传价格表，等待解析完成。解析后先看预览，确认数据列识别正常。
选择品牌和颜色根据本批次要做的商品选择对应品牌、颜色和模板要求。品牌和颜色会影响生成表格里的标题、型号和变种信息。
生成表格点击制作后，工具会根据内置最新型号表和你的价格表生成可用于 BigSeller 的上架表格。
保存并上传生成后把表格放到自动上架数据的上架表格目录，再按正常流程进行批量上传或上架。
生成表格后仍建议打开 Excel 抽查几行，重点检查品牌、型号、价格、颜色、标题和图片批次是否对应。自动生成可以省时间，但最后一眼人工确认很重要。

四、单主图库功能新增教学

04

设置页面里的“单主图库”适合只有单张主图、或者主图不按常规组图规则走的批次。开启后，工具会从单主图库目录里读取主图，而不是完全依赖常规图库分组。

  • 先在设置里开启单主图库模式。
  • 按教学提示准备单主图库目录和图片命名。
  • 确认当前模板、品牌、批次和图片文件能对应上。
  • 正式上架前先用少量商品测试，检查主图、产品图、变种图和截图是否正确。
单主图库模式和单品牌主图随机模式不要混着理解。开启前请先确认本批次到底是“每个品牌固定单主图”，还是“每个品牌从多个主图序号里随机选择”。

五、更新后建议先做的检查

05
  • 重启工具，确认主界面能正常打开。
  • 确认 BigSeller 已登录，Chrome 状态显示正常。
  • 先用少量商品测试新增的批量工具，不要第一次就跑大批量。
  • 使用 AI 分析时，把它当作辅助检查，不要把 AI 输出直接当最终结论。
  • 上架、添加型号、开启折扣前，都建议先确认当前页面和店铺没有选错。
